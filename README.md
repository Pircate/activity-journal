# 我的运动记录

使用 Intervals.icu 真实记录的中文运动日志：[访问网站](https://pircate.github.io/movement-journal/)。

## 页面内容

拉取并保存 Intervals.icu 的全部历史运动记录。页面默认展示截至北京时间当天最近 365 天的累计距离、运动时长、运动次数和活动热力图；“全年活动”的“查看范围”可选择最近一年或任一已同步年份，切换时同步更新概览和热力图。自然年显示 1 月 1 日至 12 月 31 日，闰年含 366 天；当前年份尚未同步的日期标注为未知。最近一周的运动记录始终按北京时间当天回看 7 天，不随年份切换。可切换距离、时长和 Intervals.icu 训练负荷，也可用日期选择器或方向键查看每天的指标；选中日期后，下方列出当天全部可读取的运动记录，包括日期、运动类型、距离、运动时间、平均速度和训练负荷，无记录时隐藏列表。桌面以表格展示，宽度不超过 600px 时按活动显示纵向卡片，四项指标完整展示，无需横向滚动；全年热力图仍可横向滑动。点击最近一周的活动卡片或当天列表中的运动行或卡片，会在新标签页打开 Intervals.icu 对应运动记录；也支持 Tab 聚焦、Enter 打开，查看权限由 Intervals.icu 控制。

全年活动下方的运动装备库按自行车展示在用配件和累计里程，不受最近 365 天范围限制。配件列表默认折叠，点击自行车标题栏可独立展开或折叠，也支持键盘操作。切换年度或刷新时，只要装备内容未变化，就保留各车辆的展开状态和装备区域内的焦点。链条、前胎、后胎按 5000 km，飞轮按 10000 km，牙盘按 30000 km 显示更换进度；达到 80% 提示“接近建议更换里程”，达到建议里程提示“已达建议更换里程”，超出后保留实际里程。该里程仅为维护参考，不代表实际磨损程度。折叠标题直接显示已达建议更换里程、接近建议更换里程及更换里程或提醒信息待完善的配件数量，展开后优先展示需要关注的配件。共享配件标注所属车辆名称，关系由平台配件标识解析，不按名称推断。

## 手机月历与回到今天

手机端（宽度不超过 600px）默认以周一至周日的七列月历展示每日活动，可切换到全年热力图。月历沿用上方查看范围及距离／时长／负荷指标，日期下显示当天活动次数；白框表示选中日期，“今”标记北京时间今天。点选日期后同步更新日期选择器和当天明细；切换两种视图保留所选日期和指标。桌面继续显示全年热力图。

通过上个月／下个月翻月，保留所选日号；目标月份没有该日时选择月末，超出查看范围时选择最近边界日期。范围外日期不可选；自然年范围中的未来日期和未同步日期保留斜线与“待同步”提示，不当作零活动。支持左右方向键移动一天、上下移动一周，Home／End 移到周一／周日，Page Up／Down 翻月。

“回到今天”在手机和桌面均可用；当前查看历史年份时切换到最近一年并选中北京时间今天，否则直接选择今天。当天没有运动时隐藏旧的活动明细，尚未同步时显示对应提示。数据刷新、北京时间跨天时保留仍在范围内的所选日期、月历月份和视图状态，装备展开状态及历史查询不受影响。

## 历史记录查询

在最近一周记录下方展开“查看全部历史记录”，可以查询全部已同步历史，不受年度统计范围影响。按北京时间的开始／结束日期、运动类型、最短／最长距离组合筛选，点击“应用筛选”更新结果；支持日期、距离和运动时长的升降序排序，每页显示 20 条，可翻页或重置。手机端使用纵向活动卡片，点击活动可在新标签页打开 Intervals.icu 详情。

日期和距离筛选均包含边界。未提供距离的活动在未限制距离时保留，设置距离条件后排除；按距离排序时始终排在最后。日期倒置或最短距离大于最长距离时显示提示并保留上次结果。数据刷新保留筛选条件和当前页，结果页数减少时调整到最后一页；年度切换保留查询面板的展开状态、筛选和分页。详情无法读取的运动不列入结果，单独标注全部历史的缺失条数。

## 周／月运动趋势

全年活动下方增加“运动趋势”，跟随上方“查看范围”，按自然周（周一至周日）或自然月汇总。可切换距离、时长、次数和训练负荷；横向滑动查看全部周期，点击柱条后展示该周期的四项合计、前一周期对比与活动明细。每页 20 条，手机沿用纵向卡片，点击活动可打开 Intervals.icu。

边界周／月包含完整自然周期，因此可能包含所选年度或最近一年范围外的边界记录。已结束周期与上一完整周期比较；本周／本月截至北京时间今天，与上周期相同天数比较，最多截至上周期末。比较日期明确列出，不绘制尚未开始的未来周期。数据刷新保留周期、指标、选中项和分页；切换年度保留周期与指标，选中项不在新范围内时定位最新周期。

仅累计可读取指标，缺失情况单独说明；斜线柱条表示当前指标或周期数据不完整。任一比较周期含未同步日期或受限活动时不计算增减百分比；仅某项指标缺失时只暂停该项比较。上一周期为零时标明“上周期为 0”，两者相等显示“持平”，不生成无穷大增幅。训练负荷沿用 Intervals.icu，不作为训练建议。

## 力量训练指标

力量训练在近期卡片、历史列表和当天记录中以组数替代距离、平均心率替代平均速度，并使用紫色杠铃图标。纯力量训练列表显示“组数／平均心率”表头；混合列表标明两类指标，手机卡片按每条运动显示对应标签。缺失值显示“未提供”。

平均心率直接读取 Intervals.icu 的 `average_heartrate`。Intervals.icu 不提供原生组数；组数来自 COROS 的实际力量训练记录，保存在 `data/strength-sets.json`，仅含网站已有的 `activityUrl` 和 `sets`。补录时使用 Intervals.icu 的 `source=COROS` 和 `external_id` 与 COROS 的 `labelId` 精确关联，不按日期或运动名称推测；原始 COROS 标识不写入仓库。日常同步读取这份独立来源数据，保留已核对的组数；新增、修改记录的补录流程见 [网站更新说明](docs/SITE-SYNC.md)。仅力量训练采用这份补充，其他活动指标仍来自 Intervals.icu。

## 装备维护

装备区顶部的“维护摘要”按已达建议里程、接近建议里程、信息待完善汇总重点配件；同一配件按此优先级只计一类，共享配件只计一次。需要关注的配件列出当前里程、距建议里程或超出里程、缺失信息，并为每辆关联车辆提供“查看”入口；点击后展开目标车辆、定位并高亮对应配件，键盘 Enter 同样可用。其他车辆的展开状态独立保留，切换年度或无变化刷新不重建装备节点。首次未同步和没有车辆分别展示原有提示，不显示误导性的零维护统计。

在 Intervals.icu 的装备中维护自行车及配件，网站只读取信息，不提供编辑或重置操作：

- 将配件关联到自行车，也支持轮组下的外胎；已退役装备隐藏，共享配件在各所属自行车下展示。
- 链条使用 `Chain`、飞轮使用 `Cassette`、外胎使用 `Tyre`、牙盘使用 `Chainrings` 类型。前后外胎分别建配件，名称以“前胎”“后胎”开头，例如“前胎 GP5000”；未标位置的外胎照常显示，但明确提示位置未标记。
- 为每个链条、飞轮、外胎和牙盘设置唯一一个名为“更换”的提醒。每次换件后重置该提醒；重置时间按北京时间显示为最近更换日期，重置后的使用里程来自 `distance_used`。补胎液、上蜡等其他提醒不参与更换统计。
- 网站目标固定为链条及外胎 5000 km、飞轮 10000 km、牙盘 30000 km；建议平台提醒也设置相同里程，网站不修改平台设置。
- 缺少提醒、提醒重名、未提供重置日期或更换后里程时明确展示缺失；不使用购买日期或配件累计里程推断。自行车和普通配件使用平台累计里程。

历史换件需要单独补录：Intervals.icu 新建或更新提醒会忽略传入的历史 `last_reset`，仅修改购买日期也不会重算提醒。补录时创建零里程配件，将已知实际装车日期写入 `purchased`，先创建从零开始的“更换”提醒，再关联自行车。活动完整时可读取该配件 `/calc` 的统计并保存；已有用户确认的里程基准时应保留该基准，避免用不完整活动重算覆盖。实际更换日期以“运动装备库更换记录：”开头的 JSON 行保存在该配件备注中，字段为 `date`（日期未知时为 `null`）、`reminderId`、`resetAt`、`baseline`（提醒的起始距离、时间、次数数组）。网站只在提醒标识、重置时刻和起始计数均与补录时一致时使用这个明确记录的日期；未知日期显示“未记录”，之后重置提醒自动使用新的重置日期。备注内容及其中的内部标识不会发布。

青野与 R200 共用同一个链条和牙盘配件，分别关联到两个装备条目，平台负责累计两边的新骑行里程。外胎仅关联青野。飞轮各自独立：R200 飞轮从 R200 购买日起累计，青野飞轮承接原 TCR 飞轮拆装前的里程（TCR 累计减去 TCR 现飞轮使用里程），此后随青野的新骑行累加，两边互不重复计算。网站直接读取配件计数，不将两处展示的共享配件重复相加。

尚未完成首次装备同步时显示“装备尚未同步”；成功查询但没有在用自行车时才显示空列表。首次有授权的成功同步会填充装备库。

## 自动更新

每天北京时间 22:00 的「每日同步 Strava/Garmin/COROS 运动数据」任务完成三端同步后，按 [网站更新说明](docs/SITE-SYNC.md) 从 Intervals.icu 获取全部历史记录、更新本仓库并触发 GitHub Pages 发布。同步存在阻塞或失败、Intervals.icu 查询失败或返回无效记录时保留上一版数据。任务在本机 Codex 中执行，需要本机与 Codex 可运行、网络畅通且 Intervals.icu 与 GitHub 授权有效。

页面先展示 HTML 内嵌的最近一次构建快照，再在打开、从后台返回时向服务器验证 `docs/activities.json` 是否更新；页面可见时每 5 分钟再检查一次。请求使用 `no-cache`，允许浏览器通过 ETag 或 Last-Modified 验证并复用缓存；服务器不支持验证时正常下载完整数据。完整数据与北京时间日期均未变化时不重新渲染，保留装备展开状态和当前焦点，但仍更新同步状态提示。最近一年和最近一周随北京时间跨天滚动，即使请求失败也使用已有快照更新日期，尚未同步的日期不算作已确认没有运动的日期。

每条公开活动记录包含北京时间日期、中文运动类型、距离、运动时长、训练负荷和活动页面链接 `activityUrl`（含对应活动 ID）。力量训练额外公开 `sets`（组数）和 `averageHeartRate`（平均心率，bpm），缺失时为 `null`。装备仅公开名称、类型、里程和更换摘要；不发布坐标、心率明细、账号信息、额外的活动标识字段、装备标识、装备备注或凭据。

## 同步脚本

使用 Node.js 22 或更新版本。先在仓库外创建 `~/.config/interval-icu/config.json`：

```json
{
  "INTERVALS_ICU_API_KEY": "你的个人 API Key"
}
```

API Key 从 [Intervals.icu 设置](https://intervals.icu/settings) 底部 Developer Settings 获取。目录权限设为 `700`，配置文件权限设为 `600`。脚本每次运行直接读取该文件。

不要将凭据写入代码、公开 JSON 或 Git。脚本先解析当前账号，再查询全部历史活动及装备列表，全部校验成功后原子替换同一份公开快照。活动或装备任一请求失败时均保留上一版。重复运行不会累积重复记录；运动基础指标仅使用 Intervals.icu，力量训练组数使用上述已核对的 COROS 补充数据。

```sh
node scripts/update-data.mjs
node scripts/build.mjs
node --test scripts/*.test.mjs
```

字段来自 [官方 API 文档](https://intervals.icu/api-docs.html)：`distance` 从米转为公里，`moving_time` 为运动秒数，`icu_training_load` 为活动训练负荷；力量训练的平均心率来自 `average_heartrate`，零值或缺失值记为 `null`。使用 UTC 开始时间 `start_date` 转换北京时间日期；API 从 1900-01-01 起查询历史活动，上界比北京时间今天扩大一天，再按北京时间裁剪；达到单次 10000 条上限时自动二分为不重叠的日期范围，直至每段结果可确认完整。保留同一天的多次运动，不按日期去重。

API 不提供部分 Strava 来源活动的完整内容；这些记录仅在 `unavailableActivities` 中保留平台提供的当地日期，页面明确标注缺失，不计入距离、时长和次数。其他缺失运动时长、重复活动 ID、无效记录或单日仍达到查询上限的情况会让整次同步失败并保留旧文件。不使用旧来源的数据补齐；可读取活动缺失的距离和负荷保留为空。

`period.start` 为最早记录所在年的元旦（至少覆盖最近一年），`period.end` 为同步时的北京时间当天；年份选项包含此范围内的所有年份，空年也可查看。

`activities.json` 顶层包含 `period`、`syncedAt`、`activities`、`unavailableActivities` 和 `gearLibrary`。活动的 `activityUrl` 只接受 `https://intervals.icu/activities/` 加平台活动 ID；兼容尚无链接的旧活动快照，这些卡片不提供跳转。`gearLibrary` 首次未同步为 `null`，成功同步后为自行车数组；每辆车仅含 `name`、`type`、`distanceKm`、`components`。配件含 `name`、`type`、`distanceKm`、`replacement`；共享配件额外含 `sharedBy` 车辆名称数组和 `sharedGroup` 正整数分组号；分组号仅在本份快照内标记同一共享配件，按平台原始配件关系生成，不含原始装备标识。同名、同里程的不同配件仍有不同分组，不按名称猜测共享关系；共享分组的归属和使用信息必须一致，否则拒绝更新。普通配件的 `replacement` 为 `null`；重点配件的更换摘要包含 `status`（`available`、`missing-reminder` 或 `duplicate-reminder`）、`date`、`distanceKm`，其中未知日期和里程为 `null`。不接受缺少装备字段的旧数据结构。

同步与构建成功后，将更新文件提交并推送到 `main`，GitHub Pages 从 `docs/` 自动发布。网页只读取同源公开 JSON，凭据仅在本机脚本运行时使用。
