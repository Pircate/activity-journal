## 数值与时长展示

首屏按个人资料、最近七天摘要、活动记录的顺序排列；摘要展示次数、距离、运动时长和累计负荷，桌面横向展示，手机分两列。累计负荷使用 Intervals.icu 的训练负荷，仅累计已提供值；部分缺失时注明，全部缺失显示“—”，没有运动时显示 0，并保留未同步和详情不可读取提示。

距离统一显示为 `km`，固定两位小数并使用千分位；平均速度为一位小数的 `km/h`，训练负荷最多一位小数。最近一周的运动卡片展示单次活动的累计爬升，来自 Intervals.icu 的 `total_elevation_gain`，公开字段为可选的 `elevationGain`；单位为 `m`，最多一位小数并使用千分位，零值正常显示，缺失时显示“未提供”。活动、汇总和个人最佳用时统一使用 `时:分:秒`，不足一小时保留 `0:`，累计超过 24 小时不折算为天。跑步等运动的配速仍为 `分:秒 /km`，游泳为 `分:秒 /100m`；时长柱图和分享图的坐标轴使用标明单位的小时数。月报／年报图片和装备里程沿用相同展示规则。展示格式不修改原始快照或统计精度。

近期卡片的指标标签采用统一的 SVG 线性图标：距离用带起终点的曲线路线、时长用秒表、速度用仪表盘、爬升用上升折线；配速、游泳配速、组数与心率使用同风格图标。图标按 24px 网格绘制，描边为 1.75px，主指标显示 18px、副指标显示 16px，沿用次级灰色；图标在左，数值与单位在右，垂直居中对齐。中文标签对读屏可见，鼠标悬停卡片可查看完整指标说明。

近期记录卡片、全部历史列表和当天明细共用一套运动类型图标，覆盖同步器支持的 36 种运动。骑行用自行车、跑步用跑者、游泳用泳者与水波、力量训练用杠铃、足球用足球、椭圆机用器械轮廓；虚拟运动以屏幕区分，越野跑与山地骑行加入山形，电助力加入闪电。全部按 24px 网格绘制，线性图标使用 1.75px 圆角描边；跑步与越野跑参照运动选择页，采用黄色实心跑者与较粗的四肢轮廓，越野跑在脚下加入实心山形。骑行为绿色、步行与徒步为黄色、水上运动为蓝色、室内训练为紫色。图标始终搭配中文类型文字，未知类型显示中性运动标记。

## 页面设计

页面以数据、图表和操作为主，导航与栏目标题使用短文案。页面只保留页脚“数据来自 Intervals.icu · Strava · COROS”这一行来源说明，不展示其他说明段落或说明折叠入口。里程碑默认展示累计值、下一目标和进度，达成日期可展开查看。关键缺失状态、当前筛选结果和操作反馈仍直接展示，手机导航保持单行可横向滑动。

## 页面内容

保存完整运动历史，以 Strava 为活动主数据源，日常增量更新、每七天全量核对。页面默认展示截至北京时间当天最近 365 天的累计距离、运动时长、运动次数和活动热力图；“全年活动”的“查看范围”可选择最近一年或任一已同步年份，切换时同步更新概览和热力图。自然年显示 1 月 1 日至 12 月 31 日，闰年含 366 天；当前年份尚未同步的日期标注为“未同步”，不当作没有运动。

最近一周的运动记录始终按北京时间当天回看 7 天，不随年份切换。卡片与当天列表使用统一层级：主指标为距离，力量训练为组数；副指标按运动类型显示平均配速、平均速度或平均心率，缺少距离或时长时显示“未提供”，不推断数值。跑步、越野跑、虚拟跑步、步行和徒步显示每公里配速，游泳显示每百米配速，其余有距离的运动显示平均速度。可切换距离、时长和 Intervals.icu 训练负荷，也可用日期选择器或方向键查看每天的指标；选中日期后，下方列出当天全部可读取的运动记录，包括日期、运动类型、主指标、运动时间和副指标，无记录时隐藏列表。桌面以表格展示，宽度不超过 600px 时按活动显示纵向卡片，无需横向滚动；全年热力图仍可横向滑动。点击最近一周的活动卡片或当天列表中的运动行或卡片，会在新标签页打开 Strava 对应运动记录；也支持 Tab 聚焦、Enter 打开，查看权限由 Strava 控制。没有 Strava 关联的记录不提供跳转。训练负荷来自 Intervals.icu 的活动统计值，仅用于对照单次运动的训练投入，不构成训练建议。

运动趋势下方依次是个人最佳成绩、个人运动里程碑、月报／年报分享和运动装备库。运动装备库按自行车展示在用配件和累计里程，不受最近 365 天范围限制。配件列表默认折叠，点击自行车标题栏可独立展开或折叠，也支持键盘操作。切换年度或刷新时，只要装备内容未变化，就保留各车辆的展开状态和装备区域内的焦点。链条、前胎、后胎按 5000 km，飞轮按 10000 km，牙盘按 30000 km 显示更换进度；达到 80% 提示“接近建议更换里程”，达到建议里程提示“已达建议更换里程”，超出后保留实际里程。该里程仅为维护参考，不代表实际磨损程度。折叠标题直接显示已达建议更换里程、接近建议更换里程及更换里程或提醒信息待完善的配件数量，展开后优先展示需要关注的配件。共享配件标注所属车辆名称，关系由平台配件标识解析，不按名称推断。

## 年度查看范围与运动类型筛选

全年活动的“查看范围”只作用于本栏目的统计概览和每日活动视图（月历／全年热力图）；最近一周、历史记录查询、运动趋势、个人最佳成绩、个人运动里程碑和运动装备库各自独立，不随年度筛选变化。切换年份或类型时同步更新年度内容，不重建其他区域。

“运动类型分布”同时作为筛选入口：点选某个运动类型后，年度概览和每日活动视图只统计该类型，再次点选或选择“全部运动”清除。分布中的次数始终是该范围的完整记录数，便于对照筛选前后；当前范围没有该类型时仍保留所选项并显示 0 次。详情不可读取的记录没有运动类型，筛选单个类型时不计入，页面单独说明排除数量。切换年份或刷新保留当前类型筛选及筛选控件的键盘焦点。

## 三类缺失状态

每日活动视图、月历、趋势和历史记录共用同一套口径，把三种情况分开表达，避免把“没有运动”“没读到指标”“读不到详情”混为一谈：

- **未同步**：该日期不在已同步日期范围内，或晚于北京时间今天。热力图与月历使用灰色斜纹，不计入任何统计。
- **指标缺失**：活动已经读取，但该指标没有提供，使用橙色斜纹，不按 0 计入。力量训练以组数为主指标，距离本就不适用，因此不因距离为空计入缺失。
- **详情不可读取**：平台只返回当地日期，没有距离、时长和运动类型，使用蓝色交叉纹理，不计入距离、时长和次数。

当天只缺部分指标时，在原有分级颜色上叠加白色斜纹；当天既有可读取活动又有不可读取记录时，方格保留活动颜色并加蓝色虚线边框。热力图下方给出四类图例。完整统计口径保留在本文档中，页面不再展示说明折叠区。

手机端（宽度不超过 600px）默认以周一至周日的七列月历展示每日活动，可切换到全年热力图。月历沿用上方查看范围及距离／时长／负荷指标，日期下显示当天活动次数；白框表示选中日期，“今”标记北京时间今天。点选日期后同步更新日期选择器和当天明细；切换两种视图保留所选日期和指标。桌面继续显示全年热力图。

通过上个月／下个月翻月，保留所选日号；目标月份没有该日时选择月末，超出查看范围时选择最近边界日期。范围外日期不可选；自然年范围中的未来日期和未同步日期保留斜纹与“未同步”提示，不当作零活动。详情不可读取的日期显示“不可读”并加蓝色交叉纹理。支持左右方向键移动一天、上下移动一周，Home／End 移到周一／周日，Page Up／Down 翻月。

“回到今天”在手机和桌面均可用；当前查看历史年份时切换到最近一年并选中北京时间今天，否则直接选择今天。当天没有运动时隐藏旧的活动明细，尚未同步时显示对应提示。数据刷新、北京时间跨天时保留仍在范围内的所选日期、月历月份和视图状态，装备展开状态及历史查询不受影响。

## 历史记录查询

在最近一周记录下方展开“查看全部历史记录”，可以查询全部已同步历史，不受年度统计范围与“运动类型分布”筛选影响。按北京时间的开始／结束日期、运动类型、最短／最长距离组合筛选，点击“应用筛选”更新结果；支持日期、距离和运动时长的升降序排序，每页显示 20 条，可翻页或重置。手机端使用纵向活动卡片，点击活动可在新标签页打开 Intervals.icu 详情。

日期和距离筛选均包含边界。未提供距离的活动在未限制距离时保留，设置距离条件后排除；按距离排序时始终排在最后。日期倒置或最短距离大于最长距离时显示提示并保留上次结果。数据刷新保留筛选条件和当前页，结果页数减少时调整到最后一页；年度切换保留查询面板的展开状态、筛选和分页。详情不可读取的运动不列入结果，单独标注全部历史的缺失条数。

## 周／月运动趋势

![运动趋势：每月距离柱图、所选周期统计与上月同期对比](docs/images/activity-trends.png)

“运动趋势”是全年活动之后、运动装备库之前的独立栏目，顶部导航可直接跳转。栏目有独立的“查看范围”和“运动类型”筛选，默认最近一年、全部运动，不与全年活动的筛选联动；按自然周（周一至周日）或自然月汇总。按运动类型筛选时，详情不可读取的记录因缺少类型而排除。可切换距离、时长、次数和训练负荷；横向滑动查看全部周期，点击柱条后展示该周期的四项合计与前一周期对比。

边界周／月包含完整自然周期，因此可能包含所选年度或最近一年范围外的边界记录。已结束周期与上一完整周期比较；本周／本月截至北京时间今天，与上周期相同天数比较，最多截至上周期末。比较日期明确列出，不绘制尚未开始的未来周期。数据刷新保留趋势范围、运动类型、周期、指标和选中项；切换趋势范围保留周期与指标，选中项不在新范围内时定位最新周期。全年活动切换年份、类型或回到今天均不重建趋势，也不改变其筛选和所选周期。

仅累计可读取指标，缺失情况单独说明；斜线柱条表示当前指标或周期数据不完整。某一周期内没有可读取活动时，柱条值按原因显示“未同步”或“详情不可读取”，周期说明复用同一套措辞。任一比较周期含未同步日期或详情不可读取的记录时不计算增减百分比；仅某项指标缺失时只暂停该项比较。上一周期为零时标明“上周期为 0”，两者相等显示“持平”，不生成无穷大增幅。训练负荷沿用 Intervals.icu，不作为训练建议。

## 个人最佳成绩

“个人最佳成绩”是运动趋势之后、个人运动里程碑之前的独立栏目，顶部导航可直接跳转。栏目覆盖全部历史，不随其他栏目的范围与运动类型筛选变化。

跑步展示 5 公里、10 公里、半程马拉松和全程马拉松的最佳成绩，骑行展示最远距离以及 5 分钟、20 分钟的最佳平均功率（CP5、CP20）。成绩与功率取自 Intervals.icu 的全历史配速／功率曲线，曲线按运动大类聚合，因此跑步含越野跑与虚拟跑步，骑行含虚拟骑行；最远距离按本地活动快照中距离最大的骑行记录统计。每张卡片显示成绩、对应活动日期，点击成绩在新标签页打开 Intervals.icu 对应活动；曲线覆盖范围早于本地快照、查不到对应记录时显示“日期未提供”。

栏目按固定顺序展示：跑步在前、骑行在后，组内顺序不随同步顺序变化。任一曲线请求或解析失败时整次同步失败并保留上一版成绩；首次尚未同步时显示“个人最佳成绩尚未同步”。

## 个人运动里程碑

“个人运动里程碑”位于个人最佳成绩与月报／年报分享之间，覆盖全部历史，不随全年活动、运动趋势或分享报表的筛选变化。顶部显示记录以来的总里程、运动次数、活跃天数、累计时长、已达成目标数及最近达成目标；下方固定展示六条累计轨迹：

- 累计里程：全部运动已记录距离，目标为 5,000、10,000、20,000、30,000、50,000 km。
- 骑行里程：骑行与虚拟骑行，目标为 5,000、10,000、20,000、30,000 km。
- 跑步里程：跑步、越野跑与虚拟跑步，目标为 1,000、2,000、5,000、10,000 km。
- 运动次数：全部可读取记录，目标为 100、500、1,000、1,500、2,000 次。
- 活跃天数：至少有一次运动的北京时间日期，目标为 100、365、730、1,000、1,500 天。
- 运动时长：全部运动的累计时间，目标为 500、1,000、1,500、2,000 小时。

每条轨迹按活动日期依次累计，跨过目标的那次运动日期即为达成日期；同一天多次运动只计一个活跃日。进度条表示累计值占下一目标的比例，全部目标达成后显示 100%。距离未知的记录不参与距离累计，但仍计入次数、活跃天数和时长；力量训练不计距离，计入次数、活跃天数和时长。详情不可读取的记录没有可累计指标，只单独说明未参与。目标固定在前端代码中，不写入公开快照，也不新增配置项；修改目标后重建页面即可生效。里程碑只记录个人累计进程，不作为训练评价。

</p>

在个人运动里程碑下方选择自然月或自然年，点击“生成分享图片”查看预览，再点击“下载 PNG 图片”保存；手机也可长按图片保存。图片宽 1080 像素，高度随运动类型数量自动调整，沿用深色背景与橙色强调，包含姓名、周期、已记录距离、运动时长、总负荷、次数和活跃天数。下方按次数排序完整列出每种运动的距离、时长、次数与负荷，不合并隐藏少量运动。图表默认显示距离，可选择时长、次数或负荷，提供刻度和日均／月均值；数据不完整时不计算均值。

分享报表统计所选周期的全部可读取运动，独立于全年活动和运动趋势的范围、类型筛选。本月／本年截至北京时间今天，图片内标注“截至今日”；图表只画到今天，尚未开始的日期／月份不保留空柱或占位，也不计为已过周期的未同步天数。已过日期未同步、详情不可读取和指标缺失会随图片注明；全部距离缺失时显示“—”，没有可读取记录且数据不完整时不显示误导性的零运动。力量训练计入时长、次数、负荷和活跃天数，不计入距离。负荷沿用 Intervals.icu 统计值，仅作记录参考；现有快照不含累计爬升与心率区间数据，不进行推算。

预览、下载使用浏览器本地生成的同一张图片，不上传图片。调整报表周期、活动快照更新或北京时间跨天后，旧图片失效，保留仍有效的周期选择并提示重新生成。生成失败可重试；页面同时提供图片的文字摘要。

## 力量训练指标

力量训练在近期卡片、历史列表和当天记录中以组数替代距离、平均心率替代副指标，并使用紫色杠铃图标。纯力量训练列表显示“组数／平均心率”表头；混合列表按实际出现的指标合并表头（如“距离 / 组数”“平均配速 / 平均速度 / 平均心率”），手机卡片按每条运动显示对应的主副指标标签。缺失值显示“未提供”，不当作零。

平均心率读取 Strava 的 `average_heartrate`，返回缺失时显示“未提供”。组数来自 COROS 的实际力量训练，已核对组数保存在 `data/strength-sets.json`，仅含网站已有的 `activityUrl` 和 `sets`。同步使用 Intervals.icu 的 `source=COROS`、`external_id` 与 COROS 的 `labelId` 精确关联，再通过真实 Strava ID 或已核对链接合入活动；不按日期或名称猜测。原始 COROS 标识仅放在 Git 忽略的临时输入中。查询范围与活动同步一致，缺少补充时保留已知组数；流程见 [网站更新说明](docs/SITE-SYNC.md)。

## 装备维护

装备区顶部的“维护摘要”按已达建议里程、接近建议里程、信息待完善汇总重点配件；同一配件按此优先级只计一类，共享配件只计一次。需要关注的配件列出当前里程、距建议里程或超出里程、缺失信息，并为每辆关联车辆提供“查看”入口；点击后展开目标车辆、定位并高亮对应配件，键盘 Enter 同样可用。其他车辆的展开状态独立保留，切换年度或无变化刷新不重建装备节点。首次未同步和没有车辆分别展示原有提示，不显示误导性的零维护统计。

在 Intervals.icu 的装备中维护自行车及配件，网站只读取信息，不提供编辑或重置操作：

- 将配件关联到自行车，也支持轮组下的外胎；已退役装备隐藏，共享配件在各所属自行车下展示。
- 链条使用 `Chain`、飞轮使用 `Cassette`、外胎使用 `Tyre`、牙盘使用 `Chainrings` 类型。前后外胎分别建配件，名称以“前胎”“后胎”开头，例如“前胎 GP5000”；未标位置的外胎照常显示，但明确提示位置未标记。
- 为每个链条、飞轮、外胎和牙盘设置唯一一个名为“更换”的提醒。每次换件后重置该提醒；重置时间按北京时间显示为最近更换日期，重置后的使用里程来自 `distance_used`。补胎液、上蜡等其他提醒不参与更换统计。
- 网站目标固定为链条及外胎 5000 km、飞轮 10000 km、牙盘 30000 km；建议平台提醒也设置相同里程，网站不修改平台设置。
- 缺少提醒、提醒重名、未提供重置日期或更换后里程时明确展示缺失；不使用购买日期或配件累计里程推断。自行车和普通配件使用平台累计里程。

历史换件需要单独补录：Intervals.icu 新建或更新提醒会忽略传入的历史 `last_reset`，仅修改购买日期也不会重算提醒。补录时创建零里程配件，将已知实际装车日期写入 `purchased`，先创建从零开始的“更换”提醒，再关联自行车。活动完整时可读取该配件 `/calc` 的统计并保存；已有用户确认的里程基准时应保留该基准，避免用不完整活动重算覆盖。实际更换日期以“运动装备库更换记录：”开头的 JSON 行保存在该配件备注中，字段为 `date`（日期未知时为 `null`）、`reminderId`、`resetAt`、`baseline`（提醒的起始距离、时间、次数数组）。网站只在提醒标识、重置时刻和起始计数均与补录时一致时使用这个明确记录的日期；未知日期显示“未记录”，之后重置提醒自动使用新的重置日期。备注内容及其中的内部标识不会发布。

青野与 R200 共用同一个链条和牙盘配件，分别关联到两个装备条目，平台负责累计两边的新骑行里程。外胎仅关联青野。飞轮各自独立：R200 飞轮从 R200 购买日起累计，青野飞轮承接原 TCR 飞轮拆装前的里程（TCR 累计减去 TCR 现飞轮使用里程），此后随青野的新骑行累加，两边互不重复计算。网站直接读取配件计数，不将两处展示的共享配件重复相加。

尚未完成首次装备同步时显示“装备尚未同步”；成功查询但没有在用自行车时才显示空列表。首次有授权的成功同步会填充装备库。

## 自动更新

每天北京时间 22:00 的「每日同步 Strava/Garmin/COROS 运动数据」任务完成三端同步后，按 [网站更新说明](docs/SITE-SYNC.md) 执行增量同步。任务仍由本机 Codex 调度，需要本机、Codex、网络及各平台授权可用；本仓库不另建定时器。

数据来源按职责划分：Strava 提供活动日期、类型、距离、运动时长、爬升、力量训练平均心率和活动链接；Intervals.icu 补充训练负荷、跑步最佳成绩及 CP5／CP20，同时提供装备与配件维护信息；COROS 补充力量训练组数。最远骑行由合并后的完整活动快照计算。

首次运行全量核对 Strava 历史，此后日常从上次成功游标前 7 天开始查询，按真实 Strava ID 更新或新增。失败或停机期间的时间跨度完整保留；每次查询上界固定为本次任务开始时间。Strava 的时间过滤按运动发生时间，不是上传／修改时间，因此距上次全量核对满 7 天时自动再次全量核对，以发现更早的补传和修改。仅全量查询成功后检查消失的活动，并逐条查询详情确认；缺少完整读取权限、限流或请求失败时禁止删除。Intervals.icu 和 COROS 查询同一日期范围，装备每次完整读取，两条成绩曲线每次直接查询。

当前历史记录及已知负荷、组数、跨平台链接保留。未关联 Strava 的历史活动单独保留，只有平台明确返回真实关联后才合并。Strava 主指标覆盖关联活动的旧基础指标；Intervals.icu 不再覆盖这些基础指标。补充暂不可得时保留已知负荷与组数，新活动缺失时保持 `null`，不使用 Strava 相对强度代替 Intervals.icu 负荷。

页面先显示 HTML 内嵌快照，再在打开、从后台返回及可见时每 5 分钟检查同源公开 JSON。请求使用 `no-cache`，支持 ETag／Last-Modified 缓存验证。完整数据与北京时间日期未变化时不重建内容，保留当前筛选、装备展开和焦点；北京时间跨天仍会滚动统计范围。

## 同步脚本

使用 Node.js 22 或更新版本，无需新增运行时依赖。复用以下仓库外凭据：

- `~/.open-fit/strava.env`：`STRAVA_TOKEN` 或 `STRAVA_ACCESS_TOKEN`，以及自动刷新所需的 `STRAVA_CLIENT_ID`、`STRAVA_CLIENT_SECRET`、`STRAVA_REFRESH_TOKEN`。环境变量优先。须授权 `activity:read_all`；已有 scope 元数据不足时直接失败，缺少元数据时以实际私密活动返回确认删除权限，否则禁止根据 404 删除。轮换后的 token 原子保存回此文件。
- `~/.config/interval-icu/config.json`：`{"INTERVALS_ICU_API_KEY":"你的个人 API Key"}`。脚本直接读取；API Key 从 Intervals.icu 设置中的 Developer Settings 获取。

凭据不写入仓库、公开快照或日志。Unix 系统凭据目录使用 `700`、文件使用 `600`，Windows 使用当前用户访问权限。

先查看本次模式和查询范围：

```sh
node scripts/sync.mjs --plan
```

由 Codex 任务通过 COROS 连接器查询 `corosOldest` 至 `end` 的力量训练（首次从已保存历史起点查询；若 Strava 发现更早历史，入口会要求扩大范围并停止本次更新），分段至每段数量小于请求上限，将成功结果写到 Git 忽略的 `output/sync/coros-strength.json`：

```json
{
  "startDate": "1900-01-01",
  "endDate": "2026-10-24",
  "queriedAt": "2026-10-24T10:00:00.000Z",
  "records": [{"labelId":"真实 COROS 标识","sets":12}]
}
```

输入范围必须覆盖 `--plan` 的 `corosOldest` 至 `end`，完成查询的时间距运行不超过 24 小时。成功查询且确实无力量训练时 `records` 为 `[]`；查询失败不得制造空输入。

```sh
node scripts/sync.mjs --coros-input output/sync/coros-strength.json
node --test scripts/*.test.mjs
```

统一入口依次读取 Strava、Intervals.icu 活动补充与装备、两条成绩曲线，合并并校验全部数据，构建首页，然后替换正式文件；`data/sync-state.json` 最后写入，包含 UTC 格式的 `cursor`、`lastSuccessfulSyncAt`、`lastFullReconcileAt`。游标保存本次开始时间，成功时间另记；状态文件不在 `/docs` 中，不供页面读取。它与活动快照一同提交，换机器仍能继续增量同步。状态文件存在但无效时停止，不默默跳过历史。

网络、授权、记录校验或构建失败时不更新正式文件或游标。替换阶段使用回滚日志，失败恢复旧文件；进程中断后下一次先恢复未完成事务。`output/sync.lock` 防止并发写入；进程异常退出后自动识别已退出进程的遗留锁并恢复事务；锁内容异常时，确认没有同步进程，再删除此锁并重试，不删除回滚日志。发布失败保留本地成功提交，重试推送或 Pages 发布，不强推。

`node scripts/build.mjs` 仍可单独从已有公开快照重建首页。`update-data.mjs` 为 Intervals.icu 查询和装备处理模块，`update-personal-bests.mjs` 提供成绩处理；日常任务统一使用 `sync.mjs`，不再使用旧的三条独立同步命令或 Strava 历史补充文件。

公开快照结构保持不变。活动仅公开北京时间日期、中文类型、公里距离、运动时长、训练负荷、可选爬升及真实平台链接；力量训练额外含组数和平均心率。装备仅公开展示字段及维护摘要，不发布原始标识、装备备注、坐标、心率明细、原始响应或凭据。缺失指标保留为空；不会把查询失败当成零活动。日期范围从最早历史记录所在年元旦开始，至少覆盖最近一年。

同步与构建成功后，检查 diff、提交并推送 `main`，GitHub Pages 从 `/docs` 发布，最终核对线上快照时间与本次一致。
